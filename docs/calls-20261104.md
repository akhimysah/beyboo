# BEYBOO video-call trial

The Appel vidéo mode now starts a real Jitsi Meet integration instead of the simulated Liam/grandmother exchange. It generates a 128-bit random room name and provides copy, native share and external-call links. No message is sent automatically and no address book is read. Guests use a direct meet.jit.si link; the existing owner-private BEYBOO site audience is unchanged.

The Jitsi script and media iframe load only after the visitor starts an attempt. Prejoin/authentication use a rectangular viewport so their controls are accessible. A confirmed `videoConferenceJoined` event returns the viewport to the eye. Remote participants are pinned in the large video area. Microphone, camera and hangup controls remain outside the image; an expansion control changes CSS without moving/reloading the iframe.

The trial uses the phone/computer camera and microphone, not physical BEYBOO hardware. It is not WhatsApp Calling and does not consume OpenAI credits. Voice AI and promotional films remain intact. No autonomous plush movement was added.

## Lifecycle and privacy

- Host creation requires Jitsi authentication. Invitees do not need access to the BEYBOO site.
- Anyone holding the invitation can attempt to join. The UI explains that hanging up does not revoke a room URL. New links generate new random names; nothing is persisted by BEYBOO.
- Switching modes, pagehide, hangup, an external-call handoff or a fatal provider error disposes the iframe and its media. Generation guards prevent late script loads, events and promises from reopening a call after cancellation.
- Changing browser tabs does not end a video call, allowing OAuth and link sharing. This differs intentionally from the voice AI session policy.
- BEYBOO does not record the call. Media uses Jitsi; do not describe it as a proprietary/private-to-BEYBOO media service or guarantee end-to-end encryption.
- meet.jit.si is explicitly a test integration. Jitsi says production applications should use JaaS or their own deployment. The FAQ discloses this; no paid service or account was provisioned.

## Verification

- Node tests cover opt-in loading, real join and remote-participant events, event-confirmed mute state, disposal, late events, cancellation during loading, provider failure/retry, insecure-context fallback, random invitation URLs, copying and share cancellation.
- Existing voice API tests pass unchanged.
- Desktop browser checks: call mode, creation of a random link, copy feedback, external invitation opens the actual Jitsi prejoin page.
- Mobile checks at 390px and 320px: no horizontal page overflow, readable instructions and accessible actions.
- The managed preview is HTTP and correctly offers the HTTPS Jitsi fallback instead of requesting media there.
- No two-person audio/video call has been validated. This environment had no active Jitsi host authentication or usable camera/microphone. The owner-private deployed site is behind sign-in in the cloud browser. A human test with Jitsi login and a second device remains necessary, including iOS Safari and cross-network media.
